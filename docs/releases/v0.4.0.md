ロールバッジと、起動・保存・read-only・委任設定の信頼性改善をまとめた機能追加版です。PR #18・#19を取り込んでいます。依存追加やNode／DSHの基礎対応範囲の引き上げはありません。

## 主な変更

- **委任時のロール名とSVGバッジ**を、対応するWebの親／子サブエージェント一覧に表示します。18種類の固定アイコンと17の完全一致別名を備え、未知のカスタム名は中立アイコンを使います。新しいロール定義やアイコン設定を追加するものではありません。
- 表示は保存された子Session／外部activationのロールに基づきます。後から設定を編集したり `apply_current` を実行したりしても既存の子は再解釈しません。記録のない子・過去の外部CLI実行は、推測でバッジを付けません。
- メタデータ取得は任意のread-only RPCです。1要求100 ID以内、応答はロール識別情報だけで、指示・モデル・環境設定は返しません。未対応・タイムアウトでも通常の一覧操作は維持します。
- **起動時のストレージ待機と永続化確認**を修正。保存済みロール／read-onlyの復元前に子が処理を始める競合を防ぎ、準備失敗時は部分登録を片付けます。read-onlyの再固定はSessionの同期通知終了後にまとめて行います。
- 完了済み書き込みの保持や過去データの再書き込みを削減。並行flushが同じ書き込み完了を確認し、一度確認した失敗が後続のrollbackを永久に妨げないようにしました。
- 明示モデルの「既定の推論設定」は親の値を引き継がず、LLM検証不能・provider差し替え・履歴継承契約の不一致は委任前に拒否します。workflowの別realm引数でも、ネイティブの不正値検証を維持します。
- **設定画面の入力保持**を改善。一時的なnamespace消失や「保存受理済みだが表示未反映」でも入力を残し、未確認の保存を自動再試行しません。補修だけの保存も既存のHost安全確認を通します。AI管理のCAS・権限・rollbackは維持しています。

## 検証と既知の制限

- ローカルで **48スイート／1,489テスト**、lint、Host／client／testの型検査、配布ビルド整合性を確認。Node 22／24のCIも通過しています。
- 実DSH **0.2.1-rc.2** の隔離チェックで、ネイティブ委任・read-only再固定・compaction・同じ子のcold復元、workflow 18項目、管理20項目、認証付きConnection→HTTP→Gateway→各Remoteを確認しました。実モデルの有料推論は呼び出していません。
- 隔離Chromiumで **14項目**を確認。親／子／入れ子、キーボード・フォーカス、明暗テーマの現在行、読み上げ情報、320px日本語表示、再接続・再試行・破棄を検証しています。ホストのChromium sandboxが利用できなかったため、成功した信頼済みローカルfixtureは明示的な `--no-sandbox` を使用しました。これはDSHの権限設定変更ではなく、失敗・成功両方の記録を残しています。
- **実稼働GUIへの組み込み確認は未実施**です。実SlotRegistryの置換／復帰、稼働中サービスの消失／再登場、統合GUIのナビゲーションは未実行です。DSHには行単位のバッジ拡張口がないため、公開slot契約を確認した専用一覧へ置き換えます。未対応のslot／サービスでは標準一覧を残しますが、将来の全バージョン・標準UIとの完全な表示／翻訳一致は保証しません。
- メモリのみ／失敗した保存では、再起動後に外部実行のバッジが失われる場合があります。外部activation開始後の記録失敗で、開始済みの委任を失敗扱いにはしません。
- ネイティブチェックにもfixtureがあります。全DSH版・実CLI／モデル・全OSの権限・電源断時の耐久性を保証するものではありません。従来のLandlock partial enforcement／hardlinkの制限も変わりません。

## 導入について

配布アーカイブ `dsh-rolesubagents-0.4.0.tgz` と `SHA256SUMS` を添付します。公開処理では、稼働中DSHへの導入・再起動・本番プロファイルや認証設定の変更は行っていません。作業終了後に利用者が更新する場合:

```sh
dsh plugin --profile web add github:Aero123421/dsh-rolesubagents#v0.4.0
```

既存会話はロール一覧のスナップショットを維持します。新しい親の会話から利用するか、許可された親が明示的に `apply_current` を実行してください。

従来案内したDSH／pnpm 12の更新時問題は本版では修正していません。プラグイン追加・更新はpnpm 10を使い、稼働中プロファイルを不用意に更新しないでください。本リリース作業では導入・復旧コマンドを実行していません。
