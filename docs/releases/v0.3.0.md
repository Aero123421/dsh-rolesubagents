AIによるロール定義の管理を任意で許可できるようになりました。Grok Build／Piの連携、CLI診断と互換性の検証記録も含む機能追加版です。PR #14・#16の変更をまとめています。

## 主な変更

- **AIロール管理は既定OFF**。「AIによるロール管理を許可」を有効にした親だけに `manage_roles` を提供します。子には継承せず、read-onlyや呼び出し主の権限上限を実行時に確認します。
- ロール一覧／詳細、モデル候補・実行先情報、作成・更新・削除の `preview` → `apply` を追加。正式なHost APIでロールだけを版番号付きCAS保存し、ゲート、CLI設定・認証、provider routeなどは変更できません。
- 現在会話の一覧は、明示的な `apply_current` で親の今後の委任だけ更新できます。既存の子・他の会話・受理済みの委任は変更しません。古いツール参照、保存中のfork／Agent置換、破棄後の遅延起動も検査します。
- **リテラルJSONの未知項目を保持**。評価済みの値や秘密情報を書き戻さないよう、継承元や未知項目を含む `!!js`／`__jsExpr`・非対応形式のロール設定は画面／AIからの変更を拒否します。そのような設定はネイティブ編集が必要です。
- 人による画面保存でも同じ版のHost側安全確認が必要です。Host／Remoteサービス非対応・古い応答では保存せず入力を保持し、確認待ちでも明示OFFにできます。通常のロール委任は任意のAI管理機能と独立しています。
- **Grok Build／Pi** の実行先を追加。既定のworkspace-writeは既存DSHのOSファイル境界を利用し、未対応・失敗時は無制限実行へ戻しません。明示的なnativeは引き続きfull-access限定です。制限付き経路は静的APIキーを使い、ブラウザー／OAuth認証はコピーしません。
- Claudeの明示的な `nativeAcceptEdits`、再試行可能なCLI接続診断、正確な条件付き互換性記録・新旧比較を追加しました。モデル候補の取得は認証済み／利用可能／完全な一覧の証明ではありません。

詳しい仕様は [ロール管理](https://github.com/Aero123421/dsh-rolesubagents/blob/v0.3.0/docs/role-management.md)、[外部CLI](https://github.com/Aero123421/dsh-rolesubagents/blob/v0.3.0/docs/external-cli.md)、[互換性証跡](https://github.com/Aero123421/dsh-rolesubagents/blob/v0.3.0/docs/cli-compatibility.md) を参照してください。

## 対応と検証範囲

- Node `^22.19.0 || >=24.0.0`。基礎DSH範囲は `>=0.2.1-alpha.3 <0.3.0-0` ですが、任意の管理・保存機能には正式なsettings API、標準の一意な `rolesubagents` entry、安全確認Remoteが必要です。
- **1,346テスト**、Node 22／24のCI、lint・型検査・コミット済み配布ビルド整合性を確認しました。実DSH `0.2.1-rc.2` の隔離チェック20件と、実Connection→HTTP→Gateway→安全確認Remote、既存workflowチェック15件も成功しています。
- 実DSHチェックのAgent／子backend／KV acknowledgement／LLM metadataにはfixtureがあります。KVの物理disk耐久性、実モデルの応答、全CLI・全OSの実効権限やproduction導入の証明ではありません。[範囲とraw記録](https://github.com/Aero123421/dsh-rolesubagents/blob/v0.3.0/docs/role-management-validation-20261023.md) を併記しています。検証で実モデルの有料推論は呼び出していません。
- DSHの既存Linux境界は、この環境ではLandlockの**partial enforcement**です。既存hardlinkの共有書き込みは残り、inode隔離や絶対的な範囲外影響防止は保証しません。Codexのsandbox検証失敗は互換性確認済みとして扱いません。[境界の制限](https://github.com/Aero123421/dsh-rolesubagents/blob/v0.3.0/docs/host-confined-cli-validation.md) を確認してください。

## 導入について

GitHub Releaseに配布アーカイブ `dsh-rolesubagents-0.3.0.tgz` と `SHA256SUMS` を添付します。公開処理は、稼働中DSHへの導入・再起動・既存の認証設定変更を行いません。利用者が作業終了後に更新する場合の指定は次のとおりです。

```sh
dsh plugin --profile web add github:Aero123421/dsh-rolesubagents#v0.3.0
```

更新後は新しい親の会話から使ってください。既存会話は一覧のスナップショットを維持し、明示的な反映は許可された親の `apply_current` で行います。

### 既知のDSH／pnpm側の更新注意

既存リリースで案内したpnpm 12の `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` により、更新失敗時にプロファイルの `node_modules` が失われる問題は、このプラグインの公開では修正していません。プラグインの追加・更新はpnpm 10で行い、稼働中のプロファイルを不用意に更新しないでください。既に壊れた場合の復旧は、pnpm 10で `dsh plugin --profile web install` です。これは案内であり、本リリース作業でこれらの導入・復旧コマンドは実行していません。
