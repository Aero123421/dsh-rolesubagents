# v0.6.1 — compatibility and safety fixes

## English

- Preserve native activation conditions for conditional workflows on DSH 0.2.2-alpha.2. For such workflows the optional role-subagents workflow model default is not applied; native activation takes priority. Explicitly admit the tested alpha in the DSH peer ranges.
- Preserve complete prerelease/build version tokens in Claude Code, Grok Build and Pi diagnostics, and reject connection-probe results delivered after cancellation.
- Keep an unconfirmed role-settings draft when a Host-accepted write has not yet appeared in the settings mirror; the misleading destructive reload action is hidden in this state. Explicit discard is still available.
- Update bundled Zod to 4.6.7 (GHSA-mrhx-c7xc-m3w5); update development-only Vitest and Happy DOM for their advisories. The pnpm override keeps Zod versions aligned.
- Enter unlisted DSH provider/model IDs even with a catalog, and refresh model and preset lists independently. Focused or edited input survives delayed answers; stale model lists are labeled. Host validation still applies.

## 日本語

- DSH 0.2.2-alpha.2の条件付きworkflowでは、条件を外したラッパーを登録せず、Host本来の有効化条件を維持します。この場合、プラグインの任意のworkflow既定モデルは適用されません。検証したalphaのみpeer範囲に明示追加しました。
- Claude Code・Grok Build・Piのバージョン表示でpre-release/build部分を保持し、キャンセル後に到着した接続テストの成功を採用しません。
- Hostが設定保存を受け付けても設定ミラーへの反映が未確認の場合、下書きを保持し、その下書きを失わせる「最新の設定を読み込む」を隠します。明示的な破棄は引き続き可能です。
- 同梱Zodを4.6.7に更新し、開発用のVitestとHappy DOMもadvisory対応版に更新しました。
- DSHのモデル一覧がある場合も未掲載のプロバイダー・モデルIDを直接入力でき、モデルとプリセットの一覧を別々に更新できます。遅延応答が入力中の欄を置き換えず、古い一覧は明示します。使用時にはHostによる検証が必要です。

## Validation and limits

- After combining [#25](https://github.com/Aero123421/dsh-rolesubagents/pull/25), [#27](https://github.com/Aero123421/dsh-rolesubagents/pull/27) and the [#5 UI follow-up](https://github.com/Aero123421/dsh-rolesubagents/pull/28): frozen install, lint, all three TypeScript configurations, **1,605 tests in 54 files**, reproducible tracked bundles and `pnpm audit` (no known vulnerabilities) passed. The pull-request CI passed Node 22 and Node 24.
- Before the UI-only follow-up, isolated installed DSH 0.2.1-rc.2 / Node 22 and 0.2.1-rc.5 / Node 24 and 0.2.2-alpha.2 / Node 24 passed native workflow (18 / 18 / 19 checks), delegation, management (23 each) and Connection/Gateway probes. RC.5 and alpha additionally passed all seven external-runtime self cases; management and Gateway were rerun against rc.5 after the UI follow-up. Model services and CLI subprocesses are fixtures; no real model inference, coding-CLI account, or deployed GUI was tested in this release run. [Historical multi-version report](../dsh-compatibility-20261029.md) identifies its own baseline and scope.
- VM execution is **not implemented**. The separate VM design RFC remains a draft. Historical PR #5's correctness and catalog UI changes were selectively carried forward; its proposed Node/DSH minimum-version increase was intentionally not adopted.
- Publishing a release does not install or update a running profile. Back up profiles and verify the package-manager update path before installation: a known pnpm 12 minimum-age/installation failure can leave an existing profile's plugin dependencies missing. Do not assume a failed in-place update preserves them.
