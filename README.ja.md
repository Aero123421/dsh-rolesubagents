# dsh-rolesubagents

[English](README.md) | 日本語

DeepSeek Harness（DSH）のサブエージェントに「ロール」を付けるプラグインです。worker、reviewer、explorer のような役割ごとに、モデル、子への指示、コンテキスト（新規かフォーク）、読み取り専用かどうかを設定画面で決めておけます。親のエージェントは、委譲するたびに役割を選んで子を起動します。

## できること

- **ロールの定義**：名前、親向けの説明、子への指示、モデル、読み取り専用、Agent Preset を設定画面で編集できます。ロールごとにオンオフできます。
- **組み込みロール**：`general`（白紙から始まる汎用の子。公式の `subagent` 相当）と `fork`（親の会話を引き継ぐ子。公式の `subagent_fork` 相当）は削除できません。オフにはできます。
- **テンプレート**：`worker`、`explorer`、`reviewer` を同梱しています。
- **読み取り専用**：子のファイルサンドボックスを `read-only` に固定し、その後 `sandbox/mode` が広い権限に変わったら、そのイベントの通知後に `read-only` へ戻します。読み取り専用のあいだは、MCP や他プラグインの書き込み系ツールも拒否します。権限の引き上げ要求も自動で拒否され、親がフルアクセスや Auto review でも同じです。
- **キャッシュを壊さない**：ロールの指示はシステムプロンプトではなくランタイムコンテキストとして渡すので、モデルやプリセットを変えないロールの子は、親とシステムプロンプト・ツール定義が同一のままです。fork ロールは、引き継いだ会話の履歴もそのままキャッシュに乗ります。
- **セッションごとに固定**：設定の変更は新しいセッションから反映されます。実行中のセッションは、開始時のロール一覧のままです。

## 動作要件

- DSH `>=0.2.1-rc.2 <0.3.0-0`。この対応範囲をパッケージの `engines.dsh` に宣言しており、現在の DSH はプラグインの読み込み前に適合するか確認します。
- 設定画面は DSH Web（`dsh web`）のプラグイン画面に表示されます。

## インストール

DSH Web の「プラグイン → プラグインを追加」で次を入力します。

```text
github:Aero123421/dsh-rolesubagents
```

ターミナルから入れる場合（`web` プロファイル）：

```sh
dsh plugin --profile web add github:Aero123421/dsh-rolesubagents
```

再起動を求められたら DSH を再起動してください。

## 使い方

1. プラグイン画面で `dsh-rolesubagents` を開き、ロールを編集して保存します。
2. 新しいセッションを始めると、親のモデルに `delegate` ツールが見えます。ツールの説明に、有効なロールとその説明が並びます。
3. 親は `delegate({ role: "reviewer", description, prompt })` のように呼びます。`role` を省略すると `general` で起動します（`general` がオフのときは必須）。

子は公式のサブエージェントと同じ仕組みで動きます。バックグラウンドで起動し、終わると親に通知が届きます。追加の指示は `send_message` で送れます。

### ロールの項目

| 項目 | 内容 |
|---|---|
| ID | 親が指定する名前。小文字・数字・`-`・`_`、32文字まで |
| 親向けの説明 | どんなロールか、どう頼めばよいか。ツールの説明文に載ります |
| 子への指示 | 子のランタイムコンテキストに入ります。親には見えません |
| コンテキスト | 新規（spawn）か、フォーク（fork） |
| 引き継ぐ文脈 | フォークだけ。既定の「完了済みのやり取りすべて」は、親の完了済みターン（ツール結果を含む）をコピーします。「タスクのみ」は空の子を起動し、その履歴はコピーしません |
| モデル | プロバイダー・モデル・推論の強さ。モデルを指定しない場合は、親のモデルと推論の強さを引き継ぎます。明示的にモデルを指定して「モデルの既定」（Model default）を選ぶと、そのモデルの既定の推論の強さを使います。フォークでは指定できません |
| Agent Preset | 子をこのプリセット（システムプロンプトとツール一式）で起動します。新規のみ |
| 読み取り専用 | ファイルサンドボックスを `read-only` に保ち、MCP や他プラグインの書き込み系ツールを拒否します。判定はツール名です。止められない範囲は「制限」を参照 |

モデル一覧と Agent Preset の一覧は、それぞれ個別に更新・再試行できます。プロバイダーやモデルが一覧に見つからない場合は、**IDを直接入力** に切り替えて設定してください。一部のプロバイダーの一覧取得に失敗していても入力できます。入力中に一覧の取得が完了しても、入力欄とその内容は保持されます。

保存済みの設定に修復可能な問題がある場合は、問題の詳細を画面の言語で表示します。ほかの項目を変更せずに、修復後の設定だけを保存できます。

設定が一時的に取得できなくなっても、編集中の内容は保持されます。ホストの再起動後などに設定が変わっていた場合は競合を表示し、編集中の内容を残します。最新の設定を読み込むと、その編集内容は破棄されます。また、保存の応答を受け取ったあとも、ホスト側への反映を確認できない場合は編集内容を保持します。

### workflow用の既定モデル

プラグイン画面の **ワークフロー用モデル** で、プロバイダーとモデルをロールとは別に設定できます。公式 `workflow` ツール内の `agent()` で起動する子の既定モデルだけを変えます。ロールの選択、子への指示、Agent Preset、推論の強さ、読み取り専用設定は追加しません。

| workflowの `agent()` の指定 | workflow用モデル設定 | 使用するモデル |
|---|---|---|
| `provider` または `model` を明示 | 設定あり／なし | workflow標準の明示指定処理（設定の既定値は追加しません） |
| 両方とも指定なし | 設定あり | 設定したプロバイダーとモデル |
| 両方とも指定なし | 未設定 | workflow標準の親モデル継承 |

例えば `await agent("テストを調査して")` は設定したworkflow用モデルを使い、`await agent("レビューして", { provider: "other", model: "other-model" })` は明示したモデルを使います。片方だけを明示した場合も、設定した組み合わせは追加せず、もう片方はDSH標準の継承に任せます。プロバイダーの選択を空にすると既定モデルを解除できます。上部のサブエージェントスイッチをオフにすると、この既定モデルも無効になります。変更は新しいセッションから適用され、既存のセッションは再開後も記録済みの設定を使います。

実行、JSONスキーマ、上限、キャンセル、結果の返却、バックグラウンドジョブは、公式workflowツールがそのまま担当します。`workflow` がないプリセットにツールを追加することはありません。この連携はスクリプト内の通常の `agent()` をラップする方式なので、workflowエンジンの直接呼び出しや `globalThis.agent` 経由には適用しません。モデルを強制するポリシーではなく、便利な既定値です。ラップによりエラーの行番号がずれる場合があります。標準プリセットと、全体にworkflowを登録するheadless構成に対応します。他プラグインが同じエージェント自身の領域に `workflow` を登録している場合は、DSHが同一領域での置き換えを禁止するため、警告を記録して元のツールを変更しません。外部のツール変更は、各エージェントの次のプロンプト生成またはworkflow実行前に反映します。変更前のアダプターを保持していても、削除・制限されたworkflowの実行は拒否します。

### キャッシュについて

- 親と同じモデル・同じ構成のロールは、親とシステムプロンプト・ツール定義が同一なので、親のキャッシュをそのまま使えます。
- モデルを変えたロール、Agent Preset を使うロールは、親とはキャッシュを共有しません（同じロールの子どうしでは共有できます）。
- fork ロールはモデルとプリセットを変えられません。変えると、引き継いだ履歴を全部読み直すことになるためです。

## 公式の subagent ツールとの関係

このプラグインのツール名は `delegate` で、公式の `subagent` / `subagent_fork` とは衝突しません。モデルに委譲ツールを1つだけ見せたい場合は、公式のツールをオフにしてください。

- **headless など、公式ツールが DSH 全体に登録されている構成**：プロファイルの `cordis.patch.yml` に次を追加します。

  ```yaml
  - id: tool-subagent
    disabled: true
  - id: tool-subagent-fork
    disabled: true
  ```

- **DSH Web**：公式ツールは標準プリセット（Standard mode）の中にあり、プラグイン画面からはオフにできません。そのまま共存させるか、Creator モードで公式ツールを含まないプリセットを作ってください。

公式の `send_message`、`list_agents`、`interrupt_agent` はそのまま使います。オフにしないでください。

## 制限

- 読み取り専用のロールは `session/event` を監視します。広い権限への `sandbox/mode` は通知時点ですでにログに確定しているため、そのイベントを拒否したり削除したりはできません。DSH `0.2.1-rc.2` は、稼働中の Session が同期的にイベントを通知している最中の再追記を拒否します。そのため、プラグインは通知が終わったあとのマイクロタスクで `read-only` を追記し、同期的に続いた複数の変更は 1 回の再固定にまとめます。追記が拒否された場合は警告を残します。再固定の待機中も含め、ツールのガードが判定する時点で最後のモードが `read-only` でなければ、`bash`、`pwsh`、`run_code` は拒否します。再固定は、すでにガードを通過した処理や実行中の処理に、あとから制約を掛け直すものではありません。
- 読み取り専用のあいだ、そのエージェントにガードが付き、ツール本体の前に MCP や他プラグインの書き込み系を拒否します。判定は公開名だけです。
  - DSH の MCP ブリッジはツールを `mcp__<サーバー>__<ツール>` として登録し、`readOnlyHint` や `destructiveHint` はコピーしません。ヒントは参照できません。
  - 名前はトークンに分けます。書き込みを示すトークン（`write`、`delete`、`update`、`create` など）があれば、読み取りを示すトークンが同居していても拒否します。読み取りを示すトークン（`read`、`get`、`list`、`search` など）だけなら許可します。どちらでもない名前は拒否します。
  - 削除するのに `get_user` のような読み取り名のツールは止まりません。読み取りなのに書き込みらしい名前、またはどちらとも判別できない名前は拒否されます。
  - 名前が書き込みらしくなくても、外部を変えることが分かっているツールは拒否します。`plugin_manager`、ゴールとスケジュールの変更、`stagehand_*`、ターミナル操作（`terminal_open`、`terminal_send`、`terminal_close`、`terminal_signal`）が含まれます。
- `bash`、`pwsh`、`run_code` は、最後のサンドボックスモードが `read-only` のときだけツールのガードを通過できます。`terminal_read` は呼び出せます。`read-only` を強制しないサンドボックス実装では、許可したシェルがファイルを変更できます。その強制は DSH 側の仕事です。ネットワークとプロセスの可視性は、この固定の外です。`run_code` の中から呼ぶツールは同じガードを通りますが、プログラム自身のファイル書き込みはこのガードでは検査しません。
- スラッシュコマンドはツールではありません。広い権限への `sandbox/mode` を追記するコマンドも、イベント通知後に `read-only` へ再固定する対象です。このプラグインは子の承認やポリシーを再設定しません。一回限りの `sandbox_permissions` の昇格は、委譲された子に対する DSH 側の拒否に依存します。
- 「完了済みのやり取りすべて」のフォークは、その接頭辞全体（ツール結果を含む）をコピーします。設定画面、ツール説明、ツール結果、ホストのログ、子のランタイムコンテキストに出る警告は、履歴を削ったり書き換えたりしません。「タスクのみ」は新規起動のプロバイダを使うので、親のログはコピーされません。不正な fork scope はタスクのみとして保存します。新規ロールとタスクのみのフォークは、`inheritsParentContext` が true のプロバイダを拒否します。公式のフォークには、それより小さい切り出しがありません。すでにコピーされたイベントは消せません。
- 読み取り専用のエージェントは、読み取り専用でないロールや、親の会話をコピーするフォークへは委譲できません。読み取り専用の新規ロールと、タスクのみのフォークへは委譲できます。
- 別プロセスの子（codex、claude-code、acp など）には対応していません。spawn と fork のプロバイダを使います。
- 子の会話が圧縮されても、ロールの指示はランタイムコンテキストとして出し直されます。一方、最初のタスク本文は要約に置き換わります。
- Agent Preset によってはランタイムコンテキストを省略する設定があります（例：`minimal`）。その場合でも、このプラグインのロールの指示は必ず渡されますが、公式の「委譲された子です」という説明は省略されます。

## 仕組み

- DSH が完了を待つ `agent/created` イベント内で、まず `rolesubagents` ストレージドメインの初期化と、保存済みのロール・ロール一覧の読み込みを待ちます。その後、`delegate` ツールをそのエージェント自身の領域に登録し、新しい状態の書き出しを終えてから DSH が待機中の処理を開始します。ストレージの初期化中にセッションを再開しても、保存済みのロール一覧を現在の設定で上書きしません。
- 子を起動するときは子のIDを先に決め、子の作成時に子のロールをストレージドメインに記録し、読み取り専用なら最初のリクエストより前に `sandbox/mode: read-only` を追記します。この最初の固定に失敗した場合は、子を起動しません。その後の広い権限への変更は、同期的な `session/event` の通知が終わったあとのマイクロタスクで再固定します。再開時も、保存されていたモードが広い権限なら、待機中の処理を開始する前に再固定します。読み取り専用のエージェントには `tools.guard` も付き、書き込み系の呼び出しと、判定時点の最後のモードが `read-only` でない場合の `bash`、`pwsh`、`run_code` を拒否します。
- 引き継ぐ文脈が「タスクのみ」のフォークは spawn プロバイダで起動します。履歴を引き継ぐフォークは fork プロバイダで起動し、引き継いだツール結果がプロンプト注入を運び得ることをホストのログに残します。
- ロールの指示は、全体に1つ登録したランタイムコンテキストが、ストレージドメインから読み出して返します。会話の圧縮後やセッションの再開後も同じように働きます。以前の版がセッションログに書いたプラグイン記録は、引き続き読み戻します（新しい状態はストレージドメインにのみ書き、セッションログには書きません）。セッションログだけを別環境へ移しても、ストレージドメインのロール状態は引き継がれません。履歴を引き継ぐフォークには、その履歴を信頼しないよう警告も入ります。
- プラグインをアンロードすると、エージェントごとの登録を解除し、ストレージドメインが閉じるまで待ちます。アンロード後に初期化処理が完了しても、ツールを再登録しません。ストレージを開くときは既存の記録を読み込むだけで書き直さず、新しい書き込みだけを永続化します。

## 開発

```sh
pnpm install
pnpm check   # lint, typecheck, test, lib/ が最新のビルドと一致するか
pnpm build   # lib/index.js（Host）と lib/client.js（Web）を生成
pnpm check:host # 任意: インストール済みDSHでワークフローと委任の連携を検証
```

`lib/` はコミットしています。ソースを変えたら `pnpm build` して `lib/` も一緒にコミットしてください。

実DSHでの検証には、`DSH_CHECKOUT` にインストール済みの `@deepseek-ai/dsh` パッケージのディレクトリを指定します（例: `$(npm root -g)/@deepseek-ai/dsh`）。実際のワークフロー/PTC、headless起動、子エージェント管理、ストレージ、会話圧縮、追加依頼の経路を通します。外部モデル呼び出しは決定的なテスト用アダプターに置き換えるため、APIキーは不要です。委任の検証では独立した一時プロファイルを作り、証拠の保存先を表示します。`DSH_E2E_ROOT` に新しい空のディレクトリを指定すると、セッションと検証記録の保存先を選べます。読み取り専用の検証対象はDSHのツール実行時の拒否とモードの復元であり、OSサンドボックスの強制力や実際のモデルAPIの動作は検証しません。
