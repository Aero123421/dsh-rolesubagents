# dsh-rolesubagents

[English](README.md) | 日本語

DeepSeek Harness（DSH）のサブエージェントに「ロール」を付けるプラグインです。worker、reviewer、explorer のような役割ごとに、モデル、子への指示、コンテキスト（新規かフォーク）、読み取り専用かどうかを設定画面で決めておけます。親のエージェントは、委譲するたびに役割を選んで子を起動します。

ロールの子は、DSH の中ではなく、DSH のホストにインストールしたコーディングエージェントの CLI で動かすこともできます。対応しているのは **Codex CLI**、**Claude Code**、**Antigravity CLI**（`agy`）、**OpenCode** です。どちらの場合も、親は同じ `delegate` ツールを使います。

## できること

- **ロールの定義**：名前、親向けの説明、子への指示、モデル、読み取り専用、Agent Preset を設定画面で編集できます。ロールごとにオンオフできます。
- **組み込みロール**：`general`（白紙から始まる汎用の子。公式の `subagent` 相当）と `fork`（親の会話を引き継ぐ子。公式の `subagent_fork` 相当）は削除できません。オフにはできます。
- **テンプレート**：`worker`、`explorer`、`reviewer` を同梱しています。
- **読み取り専用**：子のファイルサンドボックスを `read-only` に固定し、その後 `sandbox/mode` が広い権限に変わったら、再び `read-only` を追記します。読み取り専用のあいだは、MCP や他プラグインの書き込み系ツールも拒否します。権限の引き上げ要求も自動で拒否され、親がフルアクセスや Auto review でも同じです。
- **キャッシュを壊さない**：ロールの指示はシステムプロンプトではなくランタイムコンテキストとして渡すので、モデルやプリセットを変えないロールの子は、親とシステムプロンプト・ツール定義が同一のままです。fork ロールは、引き継いだ会話の履歴もそのままキャッシュに乗ります。
- **外部 CLI で実行**：ロールの「実行先」を Codex、Claude Code、Antigravity、OpenCode のいずれかにすると、子はホスト上のその CLI として1回だけ実行されます。モデル、推論の強さ、権限プリセットは CLI 側のものを指定します。プリセットが親のセッションの権限を超えることはありません。詳しくは「[外部 CLI で動かす](#外部-cli-で動かす)」を参照してください。
- **セッションごとに固定**：設定の変更は新しいセッションから反映されます。実行中のセッションは、開始時のロール一覧のままです。ただし「外部 CLI」の設定（実行ファイルのパス、引き渡す環境変数）は例外で、委譲のたびに読み直します。

## 動作要件

- DSH `>=0.2.1-alpha.3 <0.3.0-0`（子に Agent Preset を指定する機能と、ストレージドメインサービスを使います）
- 設定画面は DSH Web（`dsh web`）のプラグイン画面に表示されます。
- 日本語の表示には dsh-japanese が必要です（[dsh-japanese](https://github.com/Aero123421/dsh-japanese)）。このプラグインは `ja` 言語を登録しません。dsh-japanese を入れて日本語を選ぶと、このプラグイン自身の日本語辞書を使います。dsh-japanese が無いときと、DSH を中文（`zh-CN`）にしているときは英語になり、メッセージキーの名前はそのまま出ません。
- CLI のロールには、その CLI がホストにインストールされていること（「[外部 CLI で動かす](#外部-cli-で動かす)」を参照）と、ホストがプラグインにサブプロセスサービスとサブエージェントのプロバイダー登録を提供していることが必要です。これらがない場合、CLI のロールはメッセージ付きで拒否されますが、DSH のロールはそのまま動きます。

## インストール

DSH Web の「プラグイン → プラグインを追加」で次を入力します。

```text
github:Aero123421/dsh-rolesubagents
```

ターミナルから入れる場合（`web` プロファイル）：

```sh
dsh plugin --profile web add github:Aero123421/dsh-rolesubagents
```

再起動を求められたら DSH を再起動してください。

## 使い方

1. プラグイン画面で `dsh-rolesubagents` を開き、ロールを編集して保存します。
2. 新しいセッションを始めると、親のモデルに `delegate` ツールが見えます。ツールの説明に、有効なロールとその説明が並びます。
3. 親は `delegate({ role: "reviewer", description, prompt })` のように呼びます。`role` を省略すると `general` で起動します（`general` がオフのときは必須）。

子は公式のサブエージェントと同じ仕組みで動きます。バックグラウンドで起動し、終わると親に通知が届きます。追加の指示は `send_message` で送れます。CLI のロールの子もバックグラウンドで起動して親に通知しますが、1回だけ実行され、`send_message` は受け付けません。

### ロールの項目

| 項目 | 内容 |
|---|---|
| ID | 親が指定する名前。小文字・数字・`-`・`_`、32文字まで |
| 実行先 | DSH（標準の子エージェント。既定）か、外部 CLI のいずれか。CLI を選ぶと、コンテキスト・引き継ぐ文脈・モデル・Agent Preset の代わりに CLI 用の項目が出ます（「[外部 CLI で動かす](#外部-cli-で動かす)」を参照）。組み込みロールは常に DSH で動きます |
| 親向けの説明 | どんなロールか、どう頼めばよいか。ツールの説明文に載ります |
| 子への指示 | 子のランタイムコンテキストに入ります。親には見えません |
| コンテキスト | 新規（spawn）か、フォーク（fork） |
| 引き継ぐ文脈 | フォークだけ。既定の「完了済みのやり取りすべて」は、親の完了済みターン（ツール結果を含む）をコピーします。「タスクのみ」は空の子を起動し、その履歴はコピーしません |
| モデル | プロバイダ・モデル・推論の強さ。空なら親と同じ。フォークでは指定できません |
| Agent Preset | 子をこのプリセット（システムプロンプトとツール一式）で起動します。新規のみ |
| 読み取り専用 | ファイルサンドボックスを `read-only` に保ち、MCP や他プラグインの書き込み系ツールを拒否します。判定はツール名です。止められない範囲は「制限」を参照 |

### workflow用の既定モデル

プラグイン画面の **ワークフロー用モデル** で、プロバイダーとモデルをロールとは別に設定できます。公式 `workflow` ツール内の `agent()` で起動する子の既定モデルだけを変えます。ロールの選択、子への指示、Agent Preset、推論の強さ、読み取り専用設定は追加しません。

| workflowの `agent()` の指定 | workflow用モデル設定 | 使用するモデル |
|---|---|---|
| `provider` または `model` を明示 | 設定あり／なし | workflow標準の明示指定処理（設定の既定値は追加しません） |
| 両方とも指定なし | 設定あり | 設定したプロバイダーとモデル |
| 両方とも指定なし | 未設定 | workflow標準の親モデル継承 |

例えば `await agent("テストを調査して")` は設定したworkflow用モデルを使い、`await agent("レビューして", { provider: "other", model: "other-model" })` は明示したモデルを使います。片方だけを明示した場合も、設定した組み合わせは追加せず、もう片方はDSH標準の継承に任せます。プロバイダーの選択を空にすると既定モデルを解除できます。上部のサブエージェントスイッチをオフにすると、この既定モデルも無効になります。変更は新しいセッションから適用され、既存のセッションは再開後も記録済みの設定を使います。

実行、JSONスキーマ、上限、キャンセル、結果の返却、バックグラウンドジョブは、公式workflowツールがそのまま担当します。`workflow` がないプリセットにツールを追加することはありません。この連携はスクリプト内の通常の `agent()` をラップする方式なので、workflowエンジンの直接呼び出しや `globalThis.agent` 経由には適用しません。モデルを強制するポリシーではなく、便利な既定値です。ラップによりエラーの行番号がずれる場合があります。標準プリセットと、全体にworkflowを登録するheadless構成に対応します。他プラグインが同じエージェント自身の領域に `workflow` を登録している場合は、DSHが同一領域での置き換えを禁止するため、警告を記録して元のツールを変更しません。外部のツール変更は、各エージェントの次のプロンプト生成またはworkflow実行前に反映します。変更前のアダプターを保持していても、削除・制限されたworkflowの実行は拒否します。

### キャッシュについて

- 親と同じモデル・同じ構成のロールは、親とシステムプロンプト・ツール定義が同一なので、親のキャッシュをそのまま使えます。
- モデルを変えたロール、Agent Preset を使うロールは、親とはキャッシュを共有しません（同じロールの子どうしでは共有できます）。
- fork ロールはモデルとプリセットを変えられません。変えると、引き継いだ履歴を全部読み直すことになるためです。

## 外部 CLI で動かす

「実行先」を CLI にしたロールでは、子は DSH のホスト上で別のプログラムとして1回だけ実行されます。親はこれまでどおり `delegate` を呼びます。ツールの説明では、こうしたロールに `(runs once in <CLI>[, read-only]; cannot receive send_message)` という注記が付き、起動結果は `started <CLI> subagent <id>` と表示されます。CLI が終わると、CLI の最終回答を載せた通常の完了通知が親に届きます。

### 必要なもの

- DSH のホストに CLI をインストールし、DSH を動かしているのと同じ OS ユーザーで、その CLI にサインインしておきます（または、API キーを持つ環境変数を引き渡します。「[外部 CLI の設定](#外部-cli-の設定)」を参照）。
- 動作を確認したバージョン：Codex CLI `codex-cli 0.163.0`、Claude Code `2.1.303`、Antigravity CLI `agy 1.4.2`、OpenCode `1.19.3`。ほかのバージョンでも多くの場合は動きます。未知のイベントは読み飛ばしますが、フラグや出力形式はリリースによって変わることがあります。

### ロールの設定

1. プラグイン画面でロールを開き、「実行先」で CLI を選びます。
2. コンテキスト・引き継ぐ文脈・モデル・Agent Preset の代わりに表示される CLI 用の項目を入力します。

   | 項目 | 内容 |
   |---|---|
   | プロバイダー | OpenCode のみ。モデルと一緒に必須です |
   | モデル | CLI 側のモデルID。空欄なら CLI に設定済みの既定のモデルを使います（OpenCode では空欄にできません）。候補は「接続をテスト」の結果か組み込みの一覧から表示されます。英数字と `. _ : @ / + - [ ]` だけからなり、`-` で始まらないIDなら、CLI が受け付けるものを何でも指定できます（プロバイダーと推論の強さも同じです） |
   | 推論の強さ | 「モデルの既定」か、CLI の推論レベルのいずれか。OpenCode ではモデルのバリアント名（自由入力） |
   | 権限 | CLI の権限プリセット（下記）のいずれか。委譲した実行は途中で承認を求めないので、ここで決めた範囲がそのまま適用されます |
   | タイムアウト（分） | この時間を過ぎると実行を止めます。1〜1440。空欄なら30分 |

3. 「読み取り専用」の意味は変わりません。選べるのは CLI の読み取り専用プリセットだけです（「[CLI での読み取り専用](#cli-での読み取り専用)」を参照）。
4. 保存して、新しいセッションを始めます。

ロールを CLI に切り替えると、フォークの設定、DSH のモデル、Agent Preset は外れます。DSH に戻すと CLI 用の項目が外れます。

### CLI ごとの詳細

どの CLI でも、タスクの本文は CLI の入力として渡し、ロールの指示（`Your role: <id>.` と、1回だけの実行であることの説明を含む）は下の表の経路で渡します。CLI に「別のエージェントの中で動いている」と思わせる継承された変数（`CLAUDECODE`、`CODEX_SANDBOX`、`CODEX_SANDBOX_NETWORK_DISABLED`）は外します。

#### Codex CLI（`codex`）

| | |
|---|---|
| 起動のしかた | `codex exec --json --ephemeral --skip-git-repo-check --color never --disable plugins --disable multi_agent -c analytics.enabled=false -c notify=[] -c shell_environment_policy.ignore_default_excludes=false -c sandbox_workspace_write.writable_roots=[] -C <cwd> -s <プリセット> [-m <モデル>] [-c model_reasoning_effort=…] [-c developer_instructions=…] -`。タスクは stdin で渡します。セッションファイルは残りません |
| プリセット | **読み取り専用** → `-s read-only`、**ワークスペースへの書き込み**（既定）→ `-s workspace-write`、**フルアクセス（サンドボックスなし）** → `-s danger-full-access`。Codex のサンドボックスで制限するので、シェルコマンドも対象です。`-s` は常に指定し、Codex の設定で追加された書き込み可能なディレクトリも空にするので、ご自身の設定でもプロジェクトの `.codex/config.toml` でも広げることはできません |
| 指示の渡し方 | `developer_instructions`（Codex 自身のプロンプトに並ぶ developer メッセージ） |
| 認証 | ホストで `codex login` するか、`CODEX_API_KEY` を引き渡します（Codex の組み込みプロバイダーは素の `OPENAI_API_KEY` を読みません）。Codex の設定にあるカスタムプロバイダーを使う場合は、そのキーの変数を引き渡します。Codex のシェルツールからは、名前に `KEY`・`SECRET`・`TOKEN` を含む変数は見えません |
| モデルと推論の強さ | モデルが空欄なら、Codex の設定（モデル、プロバイダー）がそのまま使われます。推論の強さ：none、minimal、low、medium、high、xhigh、max |
| 接続テスト | バージョン、`codex login status` によるサインイン状態（`CODEX_API_KEY` を引き渡していればサインイン済み扱い。ほかの変数（カスタムプロバイダーのキーなど）を引き渡している場合、`login status` は組み込みの OpenAI のサインインしか判断できないため、「未サインイン」の代わりに「不明」と表示します）、`codex debug models` によるモデル一覧 |

#### Claude Code（`claude`）

| | |
|---|---|
| 起動のしかた | `claude -p --output-format stream-json --verbose --no-session-persistence --strict-mcp-config [--model <モデル>] [--effort <強さ>] <プリセットのフラグ> [--append-system-prompt <指示>]`。タスクは stdin で渡します。セッションは保存せず、設定ファイルの MCP サーバーも読み込みません |

| 指示の渡し方 | `--append-system-prompt`（Claude Code のシステムプロンプトに追加） |
| 環境変数 | `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` と `DISABLE_AUTOUPDATER=1` を設定し、`CLAUDECODE` と、継承した `CLAUDE_CODE_*` をすべて外します（名前を指定して引き渡したものは残ります） |
| 認証 | ホストでの Claude Code 自身のサインイン。`ANTHROPIC_API_KEY` は自動では渡しません（print モードではサブスクリプションのサインインより優先されてしまうため）。キーで認証したい場合は、名前を指定して引き渡してください。読み取り専用とファイル編集のみは設定ファイルを読み込まないので、そこに書いた `apiKeyHelper`・モデル・`env` が効くのはフルアクセスのプリセットだけです |
| モデルと推論の強さ | モデルの別名か完全なモデルID。空欄なら Claude Code の既定です。推論の強さ：low、medium、high、xhigh、max |
| 接続テスト | バージョンと組み込みのモデル一覧。サインイン状態は「不明」と表示されます（副作用なしに確認する方法がないため）。サインインの問題は最初の実行で報告されます |

#### Antigravity CLI（`agy`）

| | |
|---|---|
| 起動のしかた | `agy --input-format stream-json --output-format stream-json --disable-slash-commands [--model <モデル>] [--effort <強さ>] [--agent dsh-rolesubagents-<nonce> [--mode accept-edits]] [--dangerously-skip-permissions] --log-file <専用の一時ディレクトリ>/agy.log`。stdin には stream-json のユーザーメッセージを1つ渡し、`AGY_CLI_DISABLE_AUTO_UPDATE=true` を設定します。実行前に `agy --output-format json models` でサインインを確認します（サインインのコード入力を待たず、約0.5秒で失敗します） |
| プリセット | **読み取り専用** → `view_file`、`grep_search`、`list_dir`、`find_by_name` だけを持つ生成エージェント、**ファイル編集のみ（シェルなし）**（既定）→ それに `write_to_file` と `replace_file_content` を加え、`--mode accept-edits` を指定したもの（指定しないと、ヘッドレスの agy は一時ディレクトリ以外への書き込みをすべて拒否します）。実行ディレクトリの外への書き込みは拒否されたままです。**フルアクセス** → agy の既定のエージェントと `--dangerously-skip-permissions` |
| 指示の渡し方 | 読み取り専用とファイル編集のみ：生成エージェント `~/.gemini/config/agents/dsh-rolesubagents-<nonce>.md` の本文（システムプロンプト）。このファイルは実行後に削除し、24時間より古い残りはプラグインの起動時に削除します。フルアクセス：タスクの前に `# Role instructions` / `# Task` として付けます（カスタムエージェントにすると agy の既定のツールとプロンプトが失われるため） |
| 認証 | agy 自身の Google サインイン。または `GEMINI_API_KEY` を引き渡し、agy の `settings.json` に `"modelProvider": "gemini"` を設定します |
| モデルと推論の強さ | 推論の強さ：low、medium、high、xhigh、max。モデルごとに使える値は一部だけで、合わない組み合わせは agy が起動時に拒否します（設定エラーとして報告） |
| 接続テスト | バージョン、サインイン状態、モデル一覧（推論の強さ付きのモデル名は、モデルとその推論の強さにまとめて表示） |

#### OpenCode（`opencode`）

| | |
|---|---|
| 起動のしかた | `opencode acp --cwd <cwd> --print-logs --log-level WARN` を Agent Client Protocol（stdin/stdout 上の JSON-RPC）で操作します。実行ごとの設定は `OPENCODE_CONFIG_CONTENT` で渡し、ファイルを書かずに OpenCode の設定に重ねます（フルアクセス未満では、プロジェクト自身の `opencode.json`、`.opencode` のエージェント・コマンド・ツール、`AGENTS.md` は読み込みません：`OPENCODE_DISABLE_PROJECT_CONFIG=1`）：モデル、プリセットを持つ一意な名前のエージェント `dsh-<nonce>`、自動更新・共有・スナップショット・タイトル生成の無効化。`OPENCODE_DB=:memory:` でセッションは保存せず、OpenCode が開くローカルサーバーにはランダムなパスワードを設定します |
| プリセット | **読み取り専用** → read（`.env` を除く）、grep、glob、list、lsp、todowrite 以外のツールをすべて拒否、**ファイル編集のみ（シェルなし）**（既定）→ それにファイル編集を加え、シェル・ワークスペース外のディレクトリ・質問は拒否。OpenCode のファイルツールは実行ディレクトリを含む git リポジトリ全体に届くので、リポジトリの最上位より下のディレクトリではファイル編集のみを拒否します（「[ワークスペースの閉じ込め](#ワークスペースの閉じ込め)」を参照）。**フルアクセス** → ワークスペース外のディレクトリ・質問・プランモードの切り替え以外はすべて許可（`.env` は読めないまま） |
| 指示の渡し方 | 専用の一時ディレクトリに置いた追加の `instructions` ファイル（`AGENTS.md` の後ろに続くシステムプロンプトの一部） |
| 認証 | OpenCode 自身のプロバイダーへのサインイン（`opencode auth login`）。またはプロバイダーのキーの変数（例：`OPENAI_API_KEY`）を引き渡します |
| モデルと推論の強さ | **プロバイダーとモデルの両方が必須**です。どちらかが欠けたロールは、OpenCode 自身の既定モデルに頼らず、オフに切り替わります。推論の強さはモデルのバリアント名（例：`high`）です。権限の確認には常に「拒否」で答え、拒否のあと回答なしで終わったターンは権限エラーとして報告します |
| 接続テスト | バージョンと、各モデルのバリアント付きのモデル一覧。サインイン状態は「不明」と表示されます |

### 権限の上限

DSH のサンドボックスや承認は CLI の中には届かないので、起動前にプラグインがプリセットを決めます。

- 呼び出し元のエージェントのロールが読み取り専用なら、上限は**読み取り専用**です。それ以外は親のセッションのサンドボックスモードに従います：`read-only` → 読み取り専用、`danger-full-access` → フルアクセス、それ以外（Auto review などの承認モードや、サンドボックスサービスがない場合を含む）→ ワークスペースへの書き込み。
- ロールのプリセットが上限を超える場合は、その CLI の上限レベルのプリセットで実行します（ホストのログに残ります）。プリセットを広げることはありません。
- フルアクセス未満では、子の作業ディレクトリは親のワークスペースのルート内でなければなりません。外側の `cwd` は拒否します。親のワークスペースのルートが分からない場合（サンドボックスサービスがない場合）は、読み取り専用の実行を除き、`cwd` の指定を拒否します。`cwd` を指定しなければ、これまでどおり親のディレクトリで動きます。
- 読み取り専用のエージェントが委譲できるのは、CLI のロールを含め、読み取り専用のロールだけです。
- DSH は外部の子を深さの上限に数えないため、次の深さが DSH の上限を超える委譲は、プラグイン自身が拒否します。CLI 自身のサブエージェントは数えません。

### ワークスペースの閉じ込め

フルアクセス未満で CLI が変更できる範囲は、次のどちらかの仕組みで制限されます。

| プリセット | 制限する仕組み |
|---|---|
| Codex の **読み取り専用**、**ワークスペースへの書き込み** | Codex の OS レベルのサンドボックス。シェルコマンドも対象で、シンボリックリンクも解決します |
| Claude Code の **読み取り専用**、**ファイル編集のみ（シェルなし）**、Antigravity の **読み取り専用**、**ファイル編集のみ**、OpenCode の **読み取り専用**、**ファイル編集のみ** | CLI 自身のツール権限。使えるツール（シェルなし）と、ファイルツールが書き込めるパスで制限します。OS のサンドボックスはありません |

後者のプリセットでワークスペースに書き込む実行の前に、プラグインは作業ディレクトリを確認し、次の場合は**委譲を拒否します**（親には短い理由が届きます）。

- ディレクトリの中に、親のワークスペース（ワークスペースが分からない場合は作業ディレクトリ）の外を指すシンボリックリンクがある場合。CLI のファイルツールはリンクをたどってしまいます。確認では `.git` も対象にし、内部ディレクトリへのリンクは実体パスごとに一度だけたどります。読み取れないディレクトリがある場合も拒否します。大きすぎて確認しきれないディレクトリ（10万項目または2秒を超えるもの）も拒否します。
- OpenCode のみ：ディレクトリが git リポジトリの最上位より下にある場合。OpenCode のファイルツールはディレクトリだけでなくリポジトリ全体に届きます（実際に、隣のディレクトリへの書き込みが成功し、`apply_patch` ではファイルをリポジトリ内のどこへでも移動できました）。リポジトリの最上位を `cwd` にして委譲してください。

Claude Code と Antigravity のファイルツールは実行ディレクトリの中にとどまります（隣のディレクトリ、リポジトリの最上位、その他の場所への書き込みが拒否されることを確認済みです）。この検査は起動時のみで、実行中に別プロセスがリンクを変更することは防ぎません。ハードリンクは検出しません。ワークスペースにハードリンクされたファイルは、その場で変更されます。拒否されたディレクトリで意図して実行したい場合は、読み取り専用のロールか、フルアクセスの親を使ってください。

また、フルアクセス未満の OpenCode は、`.opencode/plugin` または `.opencode/plugins` にコードがあるプロジェクトでの実行を拒否します。OpenCode 1.19.3 は、プロジェクトの設定を無効にしてもこのコードを起動時に実行するためです。

### CLI での読み取り専用

| CLI | 読み取り専用で行うこと |
|---|---|
| Codex | Codex の `read-only` サンドボックスで実行します |
| Claude Code | 読み取り系のツール（`Read`・`Glob`・`Grep`・`WebFetch`・`WebSearch`）だけを渡し、シェルなしの `dontAsk` モードで実行します。承認が必要な操作はすべて拒否します。設定ソース（ユーザー・プロジェクト・ローカルの設定、許可ルール、フック、`CLAUDE.md`）は読み込まないので、それらで広げることはできません。そのため、それらの設定にあるモデル・環境変数・`apiKeyHelper` も使われません |
| Antigravity | 読み取り系のツール（ファイルの表示・検索・フォルダーの一覧）だけを渡します。シェルはありません |
| OpenCode | ファイルの読み取り・検索・一覧以外のツールをすべて拒否します。`.env` ファイルも読めません。プロジェクトの OpenCode の設定と `AGENTS.md` は読み込みません。`.opencode/plugin(s)` にコードがあるプロジェクトでは実行を拒否します |

### 外部 CLI の設定

プラグイン画面の「外部 CLI」には CLI ごとのカードがあり、その CLI で動くすべてのロールに共通です。

- **実行ファイル**：絶対パス、またはホストの `PATH` から探すコマンド名。空欄なら `codex`、`claude`、`agy`、`opencode` を使います。
- **引き渡す環境変数**：変数の名前だけを、カンマかスペースで区切って入力します。値は CLI の起動時に DSH のホストプロセスの環境から読み取り、保存はしません。32個まで指定できます。「接続をテスト」では、ホストで実際に値が設定されている変数だけを数えます。
- **接続をテスト**：保存済みの設定で、実行ファイルが見つかるか、そのバージョン、（CLI が手軽に返せる場合は）サインイン状態、CLI が一覧するモデル（ロールの編集画面で候補として使います）を確認します。モデルは呼び出しません。このテストが使う RPC の経路（DSH の公開 API ではありません）をホストが提供していない場合はボタンを隠し、組み込みの候補を使います。

これらの設定は、実行中のセッションでも次の委譲から反映されます。

### 制限

- **1回だけ**：CLI の子は `send_message` を受け付けず（DSH が拒否します）、`list_agents` にも表示されません。止めるには `interrupt_agent` を使います。DSH Web では、停止ボタンのない外部タスクの行として表示されます。
- **常に空の会話から**：親の会話のフォークや Agent Preset は使えません。
- **元に戻さない**：キャンセルやタイムアウトの前に変更されたファイルは、そのまま残ります。
- **ホストの再起動**：DSH が止まると実行中の CLI も止まり、その完了通知は失われます。
- **タイムアウト**はロールごと（既定30分）。止めるときは、対応している CLI（OpenCode）にはまずキャンセルを依頼し、その後プロセスを終了させます。短い猶予のあと DSH が強制終了します。実行が終わると、CLI が残したバックグラウンドのプロセスも止めます。
- **CLI 自身の副作用**は残ります。
  - Antigravity は実行を自身の履歴に記録します（`~/.gemini` 以下に1回あたり約0.4 MB）。そのため、委譲した実行がそのディレクトリでの `agy --continue` の対象になります。また agy は常に Google の機能フラグとテレメトリのホストに接続します。
  - OpenCode はリポジトリに `<repo>/.git/opencode` を作ることがあります。また、レート制限やサーバーエラーは約1分間リトライしてから失敗します。
  - Claude Code は、DSH が root で動いていると **権限確認をすべて省略** を拒否します（`bypass-refused-as-root` 付きの設定エラーとして報告）。
  - Antigravity の **ファイル編集のみ** は、OS の一時ディレクトリへの書き込みも許可します（agy 自身のポリシー）。それ以外の、実行ディレクトリの外への書き込みは拒否され、権限エラーとして報告します。
  - Codex の **ワークスペースへの書き込み** は、`/tmp` と `$TMPDIR` への書き込みも許可します。`.git`（と `.codex`、`.agents`）は読み取り専用のままなので worker はコミットできず、ネットワークも使えません。
  - プロジェクトから読み込むもの：Codex はプロジェクトの `AGENTS.md` と、Codex で信頼したプロジェクトなら `.codex/config.toml` を読みます（上のサンドボックスのフラグが優先されます）。Claude Code の読み取り専用とファイル編集のみは、設定ファイルも `CLAUDE.md` も読み込みません。フルアクセスのプリセットでは、フックを含め、ユーザー・プロジェクト・ローカルの設定を読み込みます。OpenCode はフルアクセス未満ではご自身のグローバル設定だけを読み込み（プロジェクトの `opencode.json`、`.opencode` のファイル、`AGENTS.md` は読みません）、フルアクセスではプロジェクトの設定も読み込みます。Antigravity はプロジェクトの `AGENTS.md` を読みます。
- 失敗した実行は、`Subagent failure (CLI: Codex; category: auth; exit code: 1)` のような決まった文言の短い診断と1行のヒントとして親に届きます。CLI 自身のエラー文はホストのログにだけ残します。

### セキュリティ

- プラグインの設定に秘密は保存しません。CLI はそれぞれのサインインを使い、引き渡す環境変数は名前だけです。
- DSH は、名前に `KEY`・`TOKEN`・`SECRET`・`PASSWORD` を含む変数（と `DSH_*`）をすべての子プロセスから外します。CLI がそうした変数を受け取るのは、名前を指定して引き渡した場合だけです。
- 引き渡した変数は CLI から見え、多くの場合は CLI が実行するツール（シェルコマンドや MCP サーバー）からも見えます。その CLI に必要なものだけを引き渡してください。
- DSH のプロセスのそれ以外の変数（プロキシの設定や `*_BASE_URL` など）は、通常どおり引き継がれます。

## 公式の subagent ツールとの関係

このプラグインのツール名は `delegate` で、公式の `subagent` / `subagent_fork` とは衝突しません。モデルに委譲ツールを1つだけ見せたい場合は、公式のツールをオフにしてください。

- **headless など、公式ツールが DSH 全体に登録されている構成**：プロファイルの `cordis.patch.yml` に次を追加します。

  ```yaml
  - id: tool-subagent
    disabled: true
  - id: tool-subagent-fork
    disabled: true
  ```

- **DSH Web**：公式ツールは標準プリセット（Standard mode）の中にあり、プラグイン画面からはオフにできません。そのまま共存させるか、Creator モードで公式ツールを含まないプリセットを作ってください。

公式の `send_message`、`list_agents`、`interrupt_agent` はそのまま使います。オフにしないでください。

## 制限

- 読み取り専用のロールは `session/event` を監視します。後から来た `sandbox/mode` が `read-only` 以外なら、プラグインは `read-only` を追記します。このイベントは広い権限がログに書かれたあとで届くので、その記録は残り、その直後に `read-only` が続きます。イベント自体を取り消すことはできません。追記の最中に別の処理が再び広い権限を書くと、プラグインは 8 回までやり直したあと警告を残し、広い権限が最後の状態になります。追記が拒否された場合も、同じように警告を残します。最後のモードが `read-only` でないあいだ、`bash`、`pwsh`、`run_code` は拒否します。
- 読み取り専用のあいだ、そのエージェントにガードが付き、ツール本体の前に MCP や他プラグインの書き込み系を拒否します。判定は公開名だけです。
  - DSH の MCP ブリッジはツールを `mcp__<サーバー>__<ツール>` として登録し、`readOnlyHint` や `destructiveHint` はコピーしません。ヒントは参照できません。
  - 名前はトークンに分けます。書き込みを示すトークン（`write`、`delete`、`update`、`create` など）があれば、読み取りを示すトークンが同居していても拒否します。読み取りを示すトークン（`read`、`get`、`list`、`search` など）だけなら許可します。どちらでもない名前は拒否します。
  - 削除するのに `get_user` のような読み取り名のツールは止まりません。読み取りなのに書き込みらしい名前、またはどちらとも判別できない名前は拒否されます。
  - 名前が書き込みらしくなくても、外部を変えることが分かっているツールは拒否します。`plugin_manager`、ゴールとスケジュールの変更、`stagehand_*`、ターミナル操作（`terminal_open`、`terminal_send`、`terminal_close`、`terminal_signal`）が含まれます。
- `bash`、`pwsh`、`run_code` は、最後のサンドボックスモードが `read-only` のときだけ呼び出せます。`terminal_read` は呼び出せます。`read-only` を強制しないサンドボックス実装では、許可したシェルがファイルを変更できます。その強制は DSH 側の仕事です。ネットワークとプロセスの可視性は、この固定の外です。`run_code` の中から呼ぶツールは同じガードを通ります。ツールを呼ばずに書き込むプログラムは止まりません。
- スラッシュコマンドはツールではありません。`sandbox/mode` を追記するコマンドは、その後 `read-only` で上書きされます。このプラグインは子の承認やポリシーを再設定しません。一回限りの `sandbox_permissions` の昇格は、委譲された子に対する DSH 側の拒否に依存します。
- 「完了済みのやり取りすべて」のフォークは、その接頭辞全体（ツール結果を含む）をコピーします。設定画面、ツール説明、ツール結果、ホストのログ、子のランタイムコンテキストに出る警告は、履歴を削ったり書き換えたりしません。「タスクのみ」は新規起動のプロバイダを使うので、親のログはコピーされません。不正な fork scope はタスクのみとして保存します。新規ロールとタスクのみのフォークは、`inheritsParentContext` が true のプロバイダを拒否します。公式のフォークには、それより小さい切り出しがありません。すでにコピーされたイベントは消せません。
- 読み取り専用のエージェントは、読み取り専用でないロールや、親の会話をコピーするフォークへは委譲できません。読み取り専用の新規ロールと、タスクのみのフォークへは委譲できます。
- DSH 公式の別プロセス用プロバイダ（codex、claude-code、acp）は使いません。DSH のロールは spawn と fork のプロバイダを使い、CLI のロールはこのプラグイン独自のランナーで動きます（「[外部 CLI で動かす](#外部-cli-で動かす)」を参照。そちら固有の制限があります）。
- 子の会話が圧縮されても、ロールの指示はランタイムコンテキストとして出し直されます。一方、最初のタスク本文は要約に置き換わります。
- Agent Preset によってはランタイムコンテキストを省略する設定があります（例：`minimal`）。その場合でも、このプラグインのロールの指示は必ず渡されますが、公式の「委譲された子です」という説明は省略されます。

## 仕組み

- 各エージェントの作成時（`agent/created`）に、そのセッションのロール一覧を `rolesubagents` ストレージドメインに固定し、`delegate` ツールをそのエージェント自身の領域に登録します。
- 子を起動するときは子のIDを先に決め、子の作成時に子のロールをストレージドメインに記録し、読み取り専用なら最初のリクエストより前に `sandbox/mode: read-only` を追記します。この最初の固定に失敗した場合は、子を起動しません。その後は `session/event` でモードが変わるたびに `read-only` を追記します。再開時に保存されていたモードが `read-only` でなければ、そのときも追記します。読み取り専用のエージェントには `tools.guard` も付き、書き込み系の呼び出しを拒否します。
- 引き継ぐ文脈が「タスクのみ」のフォークは spawn プロバイダで起動します。履歴を引き継ぐフォークは fork プロバイダで起動し、引き継いだツール結果がプロンプト注入を運び得ることをホストのログに残します。
- ロールの指示は、全体に1つ登録したランタイムコンテキストが、ストレージドメインから読み出して返します。再開後も同じように働きます。以前の版がセッションログに書いたプラグイン記録は、引き続き読み戻します（新しい状態はストレージドメインにのみ書き、セッションログには書きません）。履歴を引き継ぐフォークには、その履歴を信頼しないよう警告も入ります。
- CLI のロールは別の経路を通ります。`delegate` は深さの上限と権限の上限を確認したあと、その委譲のためだけに一時的なプロバイダー（`rolesubagents:<cli>:<ロール>:<uuid>`）を登録し、DSH のサブエージェントサービスで親への通知付きの子として起動します。登録は起動の直後に外します。プロバイダーの `start` は、ホストの `ctx.subprocess` サービスで CLI を起動し、CLI ごとのやり取り（Codex・Claude Code・Antigravity は stdin のタスクと stdout の JSON 行、OpenCode は Agent Client Protocol の JSON-RPC）を行い、最後のイベントを DSH の結果に変換します。その後は DSH が実行を管理し、完了通知を届け、`interrupt_agent` で停止します。保守者向けの設計は [docs/external-cli.md](docs/external-cli.md)（英語）にあります。

```sh
pnpm check   # lint, typecheck, test, lib/ が最新のビルドと一致するか
pnpm build   # lib/index.js（Host）と lib/client.js（Web）を生成
pnpm check:host # 任意: インストール済みDSHでworkflow連携を検証
pnpm check:cli  # 任意: 実際の CLI を使った結合テスト（下記）
```

`pnpm check:cli [self|codex|claude-code|agy|opencode …]` は、実際の DSH ランタイムと実際の CLI で外部ランナーを検証します。`pnpm check` には含まれない任意のテストです。DSH のインストール（`DSH_CHECKOUT`、既定は `/opt/dsh`）と、`PATH`（または `CLI_PATH_DIR`）上の CLI が必要で、見つからない CLI はスキップします。どのケースも、CLI の接続先を `tests/support/fake-models/` のローカルな偽のモデルサーバーに向け、偽のキーと隔離したホームディレクトリで実行するので、本物の認証情報やモデル呼び出しは使いません。

`lib/` はコミットしています。ソースを変えたら `pnpm build` して `lib/` も一緒にコミットしてください。
