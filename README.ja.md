# dsh-rolesubagents

[English](README.md) | 日本語

DeepSeek Harness（DSH）のサブエージェントに「ロール」を付けるプラグインです。worker、reviewer、explorer のような役割ごとに、モデル、子への指示、コンテキスト（新規かフォーク）、読み取り専用かどうかを設定画面で決めておけます。親のエージェントは、委譲するたびに役割を選んで子を起動します。

## できること

- **ロールの定義**：名前、親向けの説明、子への指示、モデル、読み取り専用、Agent Preset を設定画面で編集できます。ロールごとにオンオフできます。
- **組み込みロール**：`general`（白紙から始まる汎用の子。公式の `subagent` 相当）と `fork`（親の会話を引き継ぐ子。公式の `subagent_fork` 相当）は削除できません。オフにはできます。
- **テンプレート**：`worker`、`explorer`、`reviewer` を同梱しています。
- **読み取り専用**：子のファイルサンドボックスを `read-only` に固定し、その後 `sandbox/mode` が広い権限に変わったら、再び `read-only` を追記します。読み取り専用のあいだは、継承された既知の読み取り専用ツールだけが動け、モードが `read-only` のときだけです。固定を戻せなかったセッションは、すべてのツールを拒否します。権限の引き上げ要求も自動で拒否され、親がフルアクセスや Auto review でも同じです。
- **キャッシュを壊さない**：ロールの指示はシステムプロンプトではなくランタイムコンテキストとして渡すので、モデルやプリセットを変えないロールの子は、親とシステムプロンプト・ツール定義が同一のままです。fork ロールは、引き継いだ会話の履歴もそのままキャッシュに乗ります。
- **セッションごとに固定**：設定の変更は新しいセッションから反映されます。実行中のセッションは、開始時のロール一覧のままです。

## 動作要件

- DSH `>=0.2.1-alpha.3 <0.3.0-0`（子に Agent Preset を指定する機能と、プラグイン記録を使います）
- 設定画面は DSH Web（`dsh web`）のプラグイン画面に表示されます。

## インストール

DSH Web の「プラグイン → プラグインを追加」で次を入力します。

```text
github:Aero123421/dsh-rolesubagents
```

ターミナルから入れる場合（`web` プロファイル）：

```sh
dsh plugin --profile web add github:Aero123421/dsh-rolesubagents
```

再起動を求められたら DSH を再起動してください。

## 使い方

1. プラグイン画面で `dsh-rolesubagents` を開き、ロールを編集して保存します。
2. 新しいセッションを始めると、親のモデルに `delegate` ツールが見えます。ツールの説明に、有効なロールとその説明が並びます。
3. 親は `delegate({ role: "reviewer", description, prompt })` のように呼びます。`role` を省略すると `general` で起動します（`general` がオフのときは必須）。

子は公式のサブエージェントと同じ仕組みで動きます。バックグラウンドで起動し、終わると親に通知が届きます。追加の指示は `send_message` で送れます。読み取り専用のエージェントが送れる相手は、読み取り専用の宛先だけです。

### ロールの項目

| 項目 | 内容 |
|---|---|
| ID | 親が指定する名前。小文字・数字・`-`・`_`、32文字まで |
| 親向けの説明 | どんなロールか、どう頼めばよいか。ツールの説明文に載ります |
| 子への指示 | 子のランタイムコンテキストに入ります。親には見えません |
| コンテキスト | 新規（spawn）か、フォーク（fork） |
| 引き継ぐ文脈 | フォークだけ。既定の「完了済みのやり取りすべて」は、親の完了済みターン（ツール結果を含む）をコピーします。「タスクのみ」は空の子を起動し、その履歴はコピーしません |
| モデル | プロバイダ・モデル・推論の強さ。空なら親と同じ。フォークでは指定できません |
| Agent Preset | 子をこのプリセット（システムプロンプトとツール一式）で起動します。新規のみ |
| 読み取り専用 | ファイルサンドボックスを `read-only` に保ち、そのモードのあいだだけ、継承された既知の読み取り専用ツールを許可します。止められない範囲は「制限」を参照 |

### キャッシュについて

- 親と同じモデル・同じ構成のロールは、親とシステムプロンプト・ツール定義が同一なので、親のキャッシュをそのまま使えます。
- モデルを変えたロール、Agent Preset を使うロールは、親とはキャッシュを共有しません（同じロールの子どうしでは共有できます）。
- fork ロールはモデルとプリセットを変えられません。変えると、引き継いだ履歴を全部読み直すことになるためです。

## 公式の subagent ツールとの関係

このプラグインのツール名は `delegate` で、公式の `subagent` / `subagent_fork` とは衝突しません。モデルに委譲ツールを1つだけ見せたい場合は、公式のツールをオフにしてください。

- **headless など、公式ツールが DSH 全体に登録されている構成**：プロファイルの `cordis.patch.yml` に次を追加します。

  ```yaml
  - id: tool-subagent
    disabled: true
  - id: tool-subagent-fork
    disabled: true
  ```

- **DSH Web**：公式ツールは標準プリセット（Standard mode）の中にあり、プラグイン画面からはオフにできません。そのまま共存させるか、Creator モードで公式ツールを含まないプリセットを作ってください。

公式の `send_message`、`list_agents`、`interrupt_agent` はそのまま使います。オフにしないでください。読み取り専用のあいだ、`send_message` と `interrupt_agent` は宛先が読み取り専用のときだけ許可されます。宛先が無い、不明、または書き込みできる場合（書き込みできる親を含む）は拒否します。

## 制限

- 読み取り専用のロールは `session/event` を監視します。後から来た `sandbox/mode` が `read-only` 以外なら、プラグインは `read-only` を追記します。このイベントは広い権限がログに書かれたあとで届くので、その記録は残ります。イベント自体を取り消すことはできません。DSH はその通知の中からの追記を拒否するので、再固定はその通知が返った直後に行います。`read-only` が最新になるまでは、`bash` や `run_code` を含むすべてのツールをガードが拒否します。追記の最中に別の処理が再び広い権限を書くと、プラグインは 8 回までやり直します。それでも `read-only` にならない、または追記が拒否された場合は、警告を残し、そのセッションでは以後すべてのツールを拒否します。あとから `read-only` のイベントが来ても、拒否は残ります。起動時（再開を含む）の固定に失敗した場合は、その起動を中止します。
- 読み取り専用のあいだ、そのエージェントにガードが付き、ツール本体の前に次をすべて満たす呼び出しだけを許可します。
  - 最新のサンドボックスモードが `read-only` であり、そのセッションの再固定が一度も失敗していない。
  - ツールの実体が、ホストまたは祖先エージェントから継承したものである。より近いスコープに同名のツールが登録されていれば拒否します。`run_code` は登録できず（予約名）、上の条件を満たすときだけ許可します。許可リストにある名前のグローバルツールを別プラグインが差し替えた場合は、ホストのツールと区別できません。
  - 名前が固定の許可リストにある（`bash`、`pwsh`、`read`、`read_image`、`glob`、`grep`、`lsp`、`web_search`、`web_fetch`、MCP リソースの読み取り、いくつかのセッションとジョブの照会、`ask_user_question`、`skill`、`terminal_list`、`terminal_read`、`run_code`、および `ALLOWED_TOOLS` の残りの名前）。`query` や `fetch` という語が名前に含まれるだけでは許可しません。`postgres_query`、`mcp__db__query`、`http_fetch` は拒否します。`merge`、`destroy`、`write` などの書き込みを示す語が混ざる名前も拒否します。
  - `send_message` と `interrupt_agent` は、宛先フィールドのすべてが、生きている読み取り専用セッションを指すときだけ許可します。最新のサンドボックスモードが `read-only` で、固定に失敗しておらず、ロールが読み取り専用である必要があります。メッセージ本文、メモ、タイトル、プロンプト、trace 系のフィールドに入った文字列以外のキーは、入れ子も配列もすべて見ます。`metadata`、`id`、`destination`、`agents`、`subagent_id` も含まれます。`message` の値がオブジェクトや配列ならその中も見るので、`message: { agent_id }` は宛先です。8 段より深い値があると、その呼び出しは拒否します。そこで見つかった既知の id は、すべて生きている読み取り専用セッションでなければなりません。エージェントがいなくなったあとも sessions サービスが一覧しているセッションを含みます。宛先キーは、入れ子と複数形を含めて、`agent_id` / `agentId` / `agent_ids` / `agentIds`、`session_id` / `sessionId` / `session_ids` / `sessionIds`、`target` / `target_id` / `targetId` / `target_ids` / `targetIds`、`target_agent_id` / `targetAgentId` / `target_agent_ids` / `targetAgentIds`、`to`、`recipient` / `recipients`、`parent_id` / `parentId` / `parent_ids` / `parentIds` です。これらのキーに入った未知の id は拒否します。メッセージ本文と trace 系（`message`、`messages`、`text`、`content`、`contents`、`prompt`、`prompts`、`description`、`title`、`body`、`note`、`notes`、`trace`、`trace_id`、`traceId`、`trace_ids`、`traceIds`、`span_id`、`spanId`、`request_id`、`requestId`）に入った文字列は走査しないので、その文字列に書いた trace id や親の id では呼び出しを決めません。これらのキーの値がオブジェクトや配列なら、中を走査します。宛先が無い、宛先のログが読めない、書き込みできる宛先が1つでもある場合は拒否します。ガードが自分のセッションログを読めないときも、例外にせずその呼び出しを拒否します。
  - `delegate` は、このプラグインが登録したツールそのものが呼ばれ、かつ親の会話をコピーしない読み取り専用ロールへの委譲のときだけ許可します。同名のツールが上から登録されている場合は拒否します。
  - DSH の MCP ブリッジはツールを `mcp__<サーバー>__<ツール>` として登録し、`readOnlyHint` や `destructiveHint` はコピーしません。ヒントは参照できません。
- `bash`、`pwsh`、`run_code`、`web_fetch`、`terminal_read` が許可リストにあるのは、サンドボックスモードが `read-only` であるという前提のうえです。ガードがこれらを許可するのは、最新のモードが `read-only` で、固定に失敗していないときだけです。バックエンドがそのモードを強制しない場合、`bash`、`pwsh`、`run_code`、`terminal_read` はファイルを変更でき、`web_fetch` はネットワークを使えます。`run_code` の中から呼ぶツールは同じガードを通ります。ツールを呼ばずに書き込むプログラムは止まりません。
- スラッシュコマンドはツールではありません。`sandbox/mode` を追記するコマンドは、再固定が成功すればその後 `read-only` で上書きされます。このプラグインは子の承認やポリシーを再設定しません。一回限りの `sandbox_permissions` の昇格は、委譲された子に対する DSH 側の拒否に依存します。
- 「完了済みのやり取りすべて」のフォークは、その接頭辞全体（ツール結果を含む）をコピーします。設定画面、ツール説明、ツール結果、ホストのログ、子のランタイムコンテキストに出る警告は、履歴を削ったり書き換えたりしません。「タスクのみ」は、`inheritsParentContext` が false でないプロバイダを拒否します。この確認は、親の会話を引き継がないロールすべてにかかります。新規の spawn ロールも含みます。`prepareContinuable` の種と、起動後の子のログに許されるのは、中身のない setup と、委譲タスクの splice 1 件です。会話メッセージを含まない setup は許可します。サンドボックスモード、承認と権限のポリシー、セッションの end-seed、subagent の descriptor とモデル選択ポリシー、選択したプリセット、作業ディレクトリの変更、モデル選択、セッションタイトル、subagent カタログ、プランモード、リクエストヘッダとコンテキスト、ターンとステップの境界です。`prompt` を持たない schedule の変更も許可します。plugin 記録は `plugin:dsh-rolesubagents/` だけで、このプラグインが書くフィールドだけを許可します。`version` と `role` または `settings`、ロールでは `id`、`enabled`、`builtin`、`description`、`instructions`、`context`、`forkScope`、`model`、`agentPreset`、`readOnly` です。inbox splice は、挿入が空のとき、挿入されたメッセージがすべて作業ディレクトリ通知のとき（source がちょうど `{ kind: 'working-directory' }` で、本文がそのサービスが書く通知の1テキストに一致する）、または委譲タスク 1 件の本文が、この呼び出しの `request.prompt` と一致するときに許可します。`delivery` が `parent` のときは、その prompt のあとに host の `withContinuableReturnGuidance` を足した形も一致します。`send_message` が隣接エージェントのツールでないときは host が案内を付けないので、prompt だけも一致します。それ以外の本文は親の履歴です。タスク splice が 2 件ある場合は親の内容です。setup の文字列には上限があります。セッションタイトルは改行のない 240 文字まで、`request/context` の文字列は 256 文字まで、カタログと descriptor の label は短いか、この呼び出しの description と完全に同じときだけ許可します。対話の印が 2 つある文字列は拒否します。`request/header` のツールスキーマはそれより長くて構いません。照合済みのタスクより前では、テキストやメッセージを運ぶ型を拒否します。user、assistant、developer、system のメッセージ、assistant attempt、ツール呼び出しと結果、チームメッセージ、フィードバック、ゴール、コマンド、圧縮を含みます。そのタスクのあとでは、子自身のステップを許可します。システムプロンプト、タスクを書き戻した `user/message`、source が `user` でない host の通知、子の assistant とツールのイベントです。source が `user` で本文がタスクでない `user/message` は、起動が返ったあとに追記されても親の履歴です。`session/event` と、その後のツール呼び出しのたびに同じ確認をし、見つかれば子を cancel して dispose します。このビルドが知らないイベント型も拒否します。起動後に子のログへその履歴が見つかった場合は、その子を止め（cancel、dispose、起動ハンドルの dispose）、呼び出しを失敗させます。公式のフォークには、それより小さい切り出しがありません。すでにコピーされたイベントは消せません。不正な引き継ぎ範囲は、そのロールをオフにし、タスクのみとして扱うので、履歴は引き継ぎません。
- 制限の対象は、このプラグインが起動した子だけです。予約がある子か、ログにロール記録がある子です。公式の subagent、teams、他プラグインが起動した子は、それぞれのサンドボックスのままにします。このプラグインが起動した子のロールは、`agent/created` の source が何であっても、起動が返ったあとに通知が届いても、適用します。プロバイダが予約した ID とは別の ID で子を公開した場合は、起動が返した ID に予約を結び直します。その ID がエージェントにもセッションにも結び付かない場合は、子を止めて呼び出しを失敗させます。DSH 0.2.1-alpha.3 は、どの起動が子を始めたかをこのプラグインに伝えません。`agent/created` は `{ agent, source }` だけで、`startActivation` は子に現れるトークンを返さず、ツール呼び出しの id は子に写されず、`subagent/descriptor` の provider 名は公式の subagent ツールと同じ spawn / fork です。そのため `delegate` の実行中に現れた同じ親の子は、こちらの子だと確定できません。`startActivation` が返るまで、その子のツールはすべて拒否されます。この保留のあいだはサンドボックスを固定しません。呼び出しが返ったとき、予約または返り値の ID と一致する子にはロールが付き、読み取り専用のロールはその時点で固定します。`parentSession` の無い子は保留しません。その ID が予約または返り値と一致するときは、ガードの対象にします。それ以外の子は保留を解きます。一時的な拒否を外し、キャンセルはせず、サンドボックスはそのままです。同じ親の公式 subagent や他プラグインの子は、その 1 回の `delegate` のあいだはツールを呼べません。呼び出しが返ったあとは書き込め、このプラグインは止めません。別の親の子は保留しません。予約は、`agent/created` が消費したとき、起動が失敗したとき、予約した子またはその親が破棄されたとき、またはプラグインの停止時まで残します。時間では捨てないので、遅れて届いた `agent/created` にもガードが付きます。固定の失敗は、そのセッションが生きているあいだ（同じ ID の別オブジェクトを含む）覚えておき、エージェントの破棄時またはプラグインの停止時に忘れます。
- 読み取り専用のエージェントは、読み取り専用でないロールや、親の会話をコピーするフォークへは委譲できません。読み取り専用の新規ロールと、タスクのみのフォークへは委譲できます。
- 別プロセスの子（codex、claude-code、acp など）には対応していません。spawn と fork のプロバイダを使います。
- 子の会話が圧縮されても、ロールの指示はランタイムコンテキストとして出し直されます。一方、最初のタスク本文は要約に置き換わります。
- Agent Preset によってはランタイムコンテキストを省略する設定があります（例：`minimal`）。その場合でも、このプラグインのロールの指示は必ず渡されますが、公式の「委譲された子です」という説明は省略されます。

## 仕組み

- 各エージェントの作成時（`agent/created`）に、そのセッションのロール一覧を `plugin:dsh-rolesubagents/roles` 記録として固定し、`delegate` ツールをそのエージェント自身の領域に登録します。
- 子を起動するときは子の ID を先に予約し、`agent/created` がその子を名乗るまで、起動が失敗するまで、子または親が破棄されるまで、あるいはプラグインが止まるまで、予約を残します。時間制限はありません。source の値には依存せず、起動が返ったあとに通知が届いても同じです。起動が返した ID が予約と違う場合は、その ID にガードを結びます。呼び出しのあいだ、予約もロール記録も無い同じ親の子はすべてのツールを拒否され、サンドボックスはそのままです。呼び出しが返ると、予約と返り値の ID を結び、読み取り専用ならそのとき固定します。どちらとも一致しない子は保留を解き、止めません。エージェントにもセッションにも結び付かない ID は失敗として、その起動を止めます。結び付いた子のログに `plugin:dsh-rolesubagents/role` 記録を書き、読み取り専用なら最初のリクエストより前に `sandbox/mode: read-only` を追記します。この固定に失敗した場合は、子を起動しません。その後は `session/event` の通知が返った直後に、モードが変わっていれば `read-only` を追記します。再開時に保存されていたモードが `read-only` でなければ、そのときも追記します。再固定に失敗したセッションは、エージェントが破棄されるかプラグインが止まるまで、すべてのツールを拒否します。ガードは呼び出しのたびに最新のモードを読むので、再固定が終わる前の隙間も閉じます。予約もロール記録もなく、このプラグインが起動している親の子でもない委譲された子は、そのままにします。
- 親の会話を引き継がないロールは、親の会話をコピーしないと宣言し、`prepareContinuable` がある場合はその種に親の履歴が無いプロバイダでだけ起動します。中身のない setup は許可します。委譲タスク 1 件は、この呼び出しが送った prompt と一致する必要があります。そのタスクより前のメッセージ、他プラグインの記録、このプラグインが書かないフィールドを持つ plugin 記録、本文がホストの通知でない作業ディレクトリ splice、会話を運ぶ setup の文字列、このビルドが知らないイベント型は拒否します。タスクのあとでは子自身のステップを許可し、タスクでない `user` メッセージは拒否します。`session/event` と、その後のツール呼び出しで同じ確認を繰り返します。起動後に子のログへその履歴があれば、子を止めて呼び出しを失敗させます。履歴を引き継ぐフォークは fork プロバイダで起動し、引き継いだツール結果がプロンプト注入を運び得ることをホストのログに残します。不正な範囲のロールはオフになります。
- ロールの指示は、全体に1つ登録したランタイムコンテキストが、エージェントのセッション記録から読み出して返します。再開後も同じように働きます。履歴を引き継ぐフォークには、その履歴を信頼しないよう警告も入ります。

## 開発

```sh
pnpm install
pnpm check   # lint, typecheck, test, lib/ が最新のビルドと一致するか
pnpm build   # lib/index.js（Host）と lib/client.js（Web）を生成
```

`lib/` はコミットしています。ソースを変えたら `pnpm build` して `lib/` も一緒にコミットしてください。
